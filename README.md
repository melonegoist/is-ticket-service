# Ticket Management System (TMS)

## Описание проекта

Это пет-проект информационной системы для управления билетами на мероприятия. Система позволяет создавать, просматривать, редактировать и удалять объекты класса `Ticket`, а также связанные с ними сущности (`Person`, `Event`, `Venue`, `Coordinates`, `Location`). Все данные хранятся в реляционной базе данных PostgreSQL.

Проект реализован с использованием современных технологий Spring MVC для веб-слоя, JPA/Hibernate для работы с базой данных.

---

## Технологический стек

*   **Язык программирования:** Java 17+
*   **Фреймворк веб-слоя:** Spring MVC
*   **ORM / Persistence:** JPA 2.2+ с Hibernate и EclipseLink

*   **Управление зависимостями:** Gradle

## Структура данных

### Основные классы

#### `Ticket`
Основной класс системы. Содержит информацию о билете.
*   `id`: Уникальный идентификатор (генерируется автоматически, > 0).
*   `name`: Название билета (не может быть null или пустой строкой).
*   `coordinates`: Координаты места (объект класса `Coordinates`, не может быть null).
*   `creationDate`: Дата создания (генерируется автоматически, не может быть null).
*   `person`: Информация о владельце (объект класса `Person`, может быть null).
*   `price`: Цена билета (> 0).
*   `type`: Тип билета (enum `TicketType`, может быть null).
*   `discount`: Скидка (0 < discount <= 100, может быть null).
*   `number`: Номер билета (> 0, может быть null).
*   `venue`: Место проведения (объект класса `Venue`, может быть null).

#### `Coordinates`
Класс для хранения координат.
*   `x`: Координата X (не может быть null).
*   `y`: Координата Y (не может быть null).

#### `Person`
Класс для хранения информации о человеке.
*   `eyeColor`: Цвет глаз (enum `Color`, не может быть null).
*   `hairColor`: Цвет волос (enum `Color`, не может быть null).
*   `location`: Местоположение (объект класса `Location`, не может быть null).
*   `birthday`: День рождения (не может быть null).
*   `height`: Рост (может быть null, > 0).
*   `passportID`: Номер паспорта (не может быть null или пустой строкой).
*   `nationality`: Гражданство (enum `Country`, не может быть null).

#### `Event`
Класс для хранения информации о мероприятии.
*   `id`: Уникальный идентификатор (генерируется автоматически, > 0).
*   `name`: Название мероприятия (не может быть null или пустой строкой).
*   `minAge`: Минимальный возраст участников (не может быть null).
*   `eventType`: Тип мероприятия (enum `EventType`, может быть null).

#### `Venue`
Класс для хранения информации о месте проведения.
*   `id`: Уникальный идентификатор (генерируется автоматически, > 0).
*   `name`: Название места (не может быть null или пустой строкой).
*   `capacity`: Вместимость (> 0).
*   `type`: Тип места (enum `VenueType`, не может быть null).

#### `Location`
Класс для хранения местоположения.
*   `x`: Координата X.
*   `y`: Координата Y.
*   `z`: Координата Z.
*   `name`: Название места (длина строки <= 517, может быть null).

### Перечисления (Enums)

*   **`TicketType`**: `VIP`, `USUAL`, `BUDGETARY`, `CHEAP`.
*   **`Color`**: `GREEN`, `RED`, `BLACK`, `BLUE`, `YELLOW`.
*   **`Country`**: `FRANCE`, `SPAIN`, `THAILAND`.
*   **`EventType`**: `BASEBALL`, `BASKETBALL`, `THEATRE_PERFORMANCE`.
*   **`VenueType`**: `PUB`, `LOFT`, `OPEN_AREA`, `CINEMA`.

## Функциональные требования

### Базовые операции с объектами

Система предоставляет пользователю возможность выполнять следующие операции над объектами `Ticket`:

1.  **Создание нового объекта.**
2.  **Получение информации об объекте по его ID.**
3.  **Обновление (модификация) атрибутов объекта.**
4.  **Удаление объекта.**

Все операции выполняются на серверной части и синхронизируются с базой данных. При создании объекта `Ticket` пользователь должен иметь возможность связать его с существующими объектами `Person`, `Event` и `Venue`.

### Пользовательский интерфейс

На главном экране отображается таблица всех текущих объектов `Ticket`. Каждый атрибут объекта представлен в отдельной колонке таблицы.

*   **Пагинация:** Если количество объектов превышает размер экрана, используется пагинация.
*   **Фильтрация и сортировка:** Пользователь может фильтровать и сортировать строки таблицы по значениям любых столбцов (неполное совпадение).
*   **Редактирование из таблицы:** При переходе к обновлению объекта, он должен быть доступен для редактирования прямо из таблицы или через отдельное диалоговое окно.
*   **Автоматическое обновление:** При добавлении, удалении или изменении объекта, все клиентские интерфейсы, авторизованные в системе, должны автоматически обновляться (появиться/исчезнуть/измениться объект).

### Расширенные пользовательские операции

Дополнительно система предоставляет специальные операции:

1.  **Рассчитать сумму значений поля `number` для всех объектов.**
2.  **Вернуть массив объектов, значение поля `number` которых меньше заданного числа.**
3.  **Вернуть массив объектов, значение поля `number` которых больше заданного числа.**
4.  **Продать билет за указанную сумму указанному человеку.**
5.  **Создать новый билет на основе указанного, указав скидку в процентах и одновременно увеличив цену билета на ту же самую сумму.**

## Архитектурные особенности

*   **Хранение данных:** Все объекты сохраняются в реляционной СУБД PostgreSQL.
*   **Генерация ID:** Для генерации полей `id` используются средства базы данных.
*   **Обработка ошибок:** Система должна корректно реагировать на некорректный пользовательский ввод, ограничивая ввод недопустимых значений и информируя пользователя о причине ошибки.
*   **Синхронизация между клиентами:** При добавлении/удалении/изменении объекта, он должен автоматически появиться/исчезнуть/измениться на всех клиентах.
*   **Модульность:** Разные уровни приложения (сервисный, DAO, контроллер) должны быть отделены друг от друга, логические части ИС должны находиться в отдельных компонентах.

## Реализация

*   **База данных:** Создана схема `public` с таблицами для всех сущностей и связями между ними (внешние ключи).
*   **JPA Entities:** Все классы (`Ticket`, `Person`, `Event`, `Venue`, `Coordinates`, `Location`) реализованы как JPA-сущности.
*   **Spring MVC:** Контроллеры обрабатывают HTTP-запросы, вызывают сервисы, возвращают модели и представления.
*   **Сервисный слой:** Содержит бизнес-логику, взаимодействует с репозиториями.
*   **Репозитории:** Интерфейсы, расширяющие `JpaRepository`, для выполнения CRUD-операций.
*   **Валидация:** Используется Bean Validation (JSR 380) для проверки данных на уровне сущностей и DTO.
*   **Шаблоны:** Использованы шаблоны проектирования (например, Repository, Service, MVC).

## Запуск проекта

1.  Установите JDK 17+ и Maven/Gradle.
2.  Установите и запустите PostgreSQL.
3.  Создайте базу данных `test` и пользователя `test` с паролем `test`.
4.  Склонируйте репозиторий.
5.  Откройте проект в IDE (например, IntelliJ IDEA или Eclipse).
6.  Настройте подключение к БД в файле `application.properties` или `persistence.xml`.
7.  Соберите проект (`gradle build`).
8.  Запустите приложение (через IDE или командной строкой).
9.  Откройте браузер и перейдите по адресу `http://localhost:8080`.
